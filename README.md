# かたちのアトリエ

暗い背景に置いた白い紙の写真から形を取り込み、その内側だけにお絵描きできるWebアプリです。HTML / CSS / JavaScriptのみで動作し、ビルド・外部ライブラリ・APIキー・バックエンドは不要です。写真を外部に送信しません。

## 起動

リポジトリのルートで次を実行し、http://localhost:4173 を開きます。

```sh
python3 -m http.server 4173
```

Node.js / npm がある環境では `npm start` でも起動できます。JavaScript ModulesとWeb Workerを使用するため、`index.html` のダブルクリック（`file://`）ではなくHTTPで開いてください。

## GitHub Pages

公開準備とiPadを含む実機テストの詳しい手順は **[公開・実機テストガイド](docs/PUBLISHING.md)** を参照してください。

1. このリポジトリへファイルをコミットしてpushします。
2. GitHubのリポジトリ設定で **Pages → Deploy from a branch** を選択します。
3. 公開したいブランチの **/ (root)** を指定します。

ルートの `index.html` が入口です。すべて相対パスのため、`https://<ユーザー名>.github.io/<リポジトリ名>/` でも動作します。`.nojekyll` を同梱しています。今回の実装作業ではリモートへのpushや公開設定の変更は行っていません。

## 使い方

1. **形を取り込む** — 「写真を撮る」または「画像を選ぶ」。カメラ入力は `capture="environment"` を指定しています。スマートフォンでは撮影画面や撮影方法の選択肢が開きます（OS・ブラウザーに依存）。PCでは通常ファイル選択になります。写真がなくても「おためしの形で遊ぶ」で全工程を試せます。
2. **輪郭を確認** — 元写真の上に青い輪郭を表示します。白さの判定を調整し、「この輪郭でOK」で進みます。
3. **お絵描き** — ペン、円／楕円・四角形・三角形・星型・ハート型、8色のパレット・自由色、太さ、消しゴム、Undo / Redo、全消去を使用できます。全消去自体もUndo可能です。輪郭の表示と太さを変更できます。
4. **保存** — 白背景・描画・表示中の輪郭を合成したPNGを保存します。輪郭非表示ならPNGにも輪郭を含めません。元写真の背景や色は入りません。スマートフォンでダウンロードが使えない場合は、保存プレビューの画像を長押ししてください。

図形は始点から終点へドラッグして位置と大きさを決めます。ドラッグ中はプレビューし、離すと確定します。全図形は選択中の色とペンの太さを使った輪郭線のみで、塗りつぶしはありません。逆方向のドラッグにも対応し、紙の外側や穴には描画されません。図形1個を1操作としてUndo / Redoでき、全消去・PNGにも含まれます。図形選択中に色を変えても選択した図形を維持します。

マウス・指・ペンの入力にはPointer Eventsを使用し、描画中のスクロールを抑制します。PCでは `Ctrl / ⌘ + Z` でUndo、`Ctrl / ⌘ + Shift + Z` または `Ctrl + Y` でRedoできます。

## 輪郭抽出と制約

- ブラウザーによる画像デコードでEXIF orientationを反映し、手動で二重回転させません。
- メモリー消費とスマートフォンの処理時間を抑えるため、長辺が2,048pxを超える画像は縦横比を保って縮小します。小さい画像は拡大しません。
- 輝度をしきい値で二値化し、上下左右で接続した最大領域を紙として選択します。
- 処理解像度での画素境界をそのまま輪郭にします。平滑化、近似曲線、凸包、穴埋め、長方形補正、遠近補正は行いません。穴や切り込みも保持します。同一直線上の辺だけをまとめます。
- 認識はWeb Workerで行い、スライダー操作時は古い認識結果を採用しないようにしています。
- お絵描きキャンバスは紙の外接範囲に余白24pxを付けて作成します。元写真は輪郭確認だけで使用します。
- 強い影、白い背景、紙より大きな明るい物体には弱い方式です。白い紙を暗い背景に1枚置いて撮影してください。複数の離れた紙を同時に選択する機能はありません。
- 最大解像度で縮小される写真の微細な凹凸まで、撮影時の全画素で保持する仕様ではありません。輪郭の正確さは撮影条件・しきい値・処理解像度に依存します。
- HEICなどの対応はブラウザーのデコーダーに依存します。読み込めない場合はJPEG / PNG / WebPを使用してください。
- 作品はメモリー内で保持します。ページを閉じたり再読み込みすると失われるため、必要な作品はPNGで保存してください。

## ファイル構成・将来のAI拡張

| ファイル | 役割 |
| --- | --- |
| `index.html` / `styles.css` | 4ステップの画面・レスポンシブUI |
| `js/app.js` | 画面遷移、入力、ツール、Pointer Events、保存 |
| `js/image-loader.js` | EXIFを反映した写真の読み込み・解像度制限 |
| `js/recognition.mjs` | 輝度、最大連結領域、正確な画素輪郭 |
| `js/recognition-worker.js` | 輪郭抽出用Web Worker |
| `js/shapes.js` | ドラッグ範囲に合わせた5種類の図形の輪郭 |
| `js/drawing.js` | 独立レイヤー、操作履歴、描画とPNG合成 |

`Drawing` は、輪郭マスク (`maskLayer`)、将来のAI画像 (`aiLayer`)、ユーザー描画 (`userLayer`)、最前面の輪郭 (`contour`) を分離しています。元写真は `app.js` 側に保持し、`Drawing` に渡しません。

将来、生成画像をデコードして `drawing.setAIImage(image)` に渡すと、輪郭内にクリップした画像をユーザー描画の下に表示できます。消しゴム・全消去はユーザー描画だけに作用します。PNGも同じレイヤー順で合成されます。`setAIImage(null)` で画像を除去できます。

**現在、AI生成機能・AI APIへの通信・テーマや注文の入力UIは実装していません。** 将来の連携では生成処理を別モジュールに追加してください。ブラウザーに秘密のAPIキーを埋め込まない構成が必要です。

## テスト

Node.js 18以降で、外部パッケージをインストールせずに実行できます。

```sh
npm test
# または
node --test tests/*.test.mjs
```

公開構成・相対パスの3テストと、輪郭抽出の6テストを実行します。4×4の全65,536パターンで閉じた輪郭と面積の一致を検査し、穴、凹部、しきい値、空画像、画像端への接触も確認します。

ローカルサーバーで `http://localhost:4173/tests/browser.html` を開くと、実際のCanvasを使う23項目の結合テストを実行できます。

- 外側・穴への描画漏れがないこと
- Undo / Redoの画素一致、タップ、消しゴム、全消去の復元
- 輪郭の重ね順、表示切替、太さ
- 将来用画像レイヤーのクリップ・重ね順・独立性
- 描画キャンセル
- PNGを再デコードした際の寸法・白背景・描画・輪郭の画素一致
- 各図形のプレビュー・確定の一致、逆方向ドラッグ、塗りつぶしなし、色・太さ、クリップ、Undo / Redo、全消去、キャンセル、サイズなしドラッグ
- EXIF orientation 6、縦横比を維持した縮小、不正ファイル

`tests/fixtures/` は個人の写真を含まない人工的なテスト画像です。`paper.png` と回転情報付きJPEGには影と穴があります。`no-paper.png` は未検出の動作確認用です。

実装時は上記32テストの成功に加え、PCでの画像選択・しきい値・マウス描画・Undo / Redo・保存プレビュー、スマートフォン幅での表示を確認しました。実機カメラ、実機タッチ、iOS / Androidの写真アプリへの保存は実機での追加確認が必要です。内蔵ブラウザーではダウンロード完了イベントを取得できなかったため、PNG生成・内容の検証とOS側への保存完了の検証を区別しています。
